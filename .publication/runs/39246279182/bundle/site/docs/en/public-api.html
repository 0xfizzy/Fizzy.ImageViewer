Viewer and lifetime

简体中文

Configure a Viewer window and own its shutdown. Viewer is sealed; application adapters compose an instance rather than access its raw WPF window. Getting started has a complete program that waits for user closure.

IViewerCapabilities contains borrowed host-independent capabilities, global layers and stopping observation. IViewer extends it with asynchronous disposal for the owner. Viewer and ImageViewerControl implement it; window operations require IViewerWindow, implemented only by Viewer. For embedded lifetime and host shutdown, see embedding.

Configure and show

await using var viewer = new Fizzy.ImageViewer.Viewer(showWindow: false);
viewer.Title = "Inspection";
viewer.HudLabelText = "Ready";
viewer.Show();
// Keep the viewer alive for the owning feature's lifetime.

Threads and window lifetime

The optional ILogger<Viewer> constructor argument defaults to no logging. Omitting it or passing null uses NullLogger<Viewer>.Instance; pass a logger to integrate with the application logging system. new Viewer() requires no logging setup.

Construction shows the window by default. Pass showWindow: false to create a hidden viewer, configure it and subscribe to events before calling Show(). A hidden viewer has a running STA and can accept frames; its owner must await DisposeAsync() even if it is never shown. Application adapters should register their resources before showing, and dispose the viewer if their own initialization fails.

Window methods and properties synchronously dispatch to the viewer STA and throw ObjectDisposedException once disposal begins. Show restores a minimized window, shows it and requests activation. Hide hides without clearing frames, drawings or measurements. Minimize changes window state without hiding it. IsVisible follows WPF visibility (a shown minimized window is still visible); IsMinimized is independent. Minimizing an already hidden window does not implicitly show it. Visible reads/writes the window visibility setting. Setting true shows without activation or restoring minimized state; Show() explicitly restores and activates. Hidden/minimized viewers keep accepting latest input but suspend new display work, then display the latest frame on return. IsVisible is not an occlusion test. Moving offscreen, covering the window or changing focus does not suspend updates.

DisposeAsync closes the window and waits for owned background work and the STA to stop. Repeated calls observe one completion task and its fixed success or failure result. Resource cleanup failures are reported after all remaining safe cleanup and STA exit; subscriber notification failures are logged and isolated. Closed subscriptions are released when that terminal notification is delivered. Construction validates window bounds before starting the STA. If initialization fails, safe resource cleanup runs on the owning thread and background work is drained before the original exception is rethrown. If cleanup also fails, an aggregate preserves both initialization and cleanup errors. Resources whose safe detachment cannot be established remain isolated rather than being released or reused. Application adapters route user closure (Closed) and explicit adapter disposal to one idempotent cleanup task, release application resources and await the owned viewer's DisposeAsync. Keep measurement subscriptions until window cleanup finishes when the adapter forwards removal notifications. Closed is a window notification, not a substitute for awaiting disposal. There is no separate public Close method. Event callbacks run on the viewer STA; do not block them waiting for shutdown or for work that needs that dispatcher.

Frame submission retains its explicit ownership and terminal-result contract: submission after closure consumes the frame and returns Closed, rather than using the window property exception policy. Drawing and HUD handle disposal is idempotent after closure. See frame contracts and drawing contracts.

HudLabelText controls the upper-right HUD text. IsPixelInfoEnabled defaults to true and controls bottom-left pixel inspection and its query subscription; the context menu uses the same state. Both properties can be configured before showing the window. EndInteraction() cancels unfinished creation or ends editing, preserving completed measurements and edits already applied.

FitToViewport centers the full image and may choose a scale outside the ordinary wheel range of 0.01–100. At such a scale, the wheel permits steps toward that range and rejects steps farther away, so very large or small images remain navigable.

Use SetDisplayRange(range) to accept the requested grayscale mapping without waiting for display. DisplayRange reads that request; snapshots retain the last successfully committed mapping. Observe later rendering failures through DisplayFailed. See display contracts.

Draining work and independent leases

Disposal drains admitted submissions through release and public completion, including replacement cleanup on submitting threads and frozen/cancelled drops. A pixel source that ignores cancellation can delay shutdown until its work releases its leases. Programmatic disposal is not blocked by CanUserClose or a cancelling window-closing handler. Cleanup failures from owned query leases and menu pins are retained in the disposal result; ordinary query/provider failures remain query failures.

Once disposal begins, frame acquisition, snapshot capture, registration and layer operations reject new work with ObjectDisposedException; submission consumes ownership and returns Closed. Previously acquired leases and snapshots remain independently owned. Viewer does not wait for external leases or reclaim their storage early. Accepted capture/export work with independent dependencies may finish after closure.

Observe stopping without owning shutdown

IViewerLifetime.WhenStopping is a shared, read-only task implemented by both hosts and included in IViewerCapabilities. Borrow it alongside the specific capabilities an endpoint needs. Reading or awaiting it does not initiate shutdown. It completes successfully once the shared admission gate closes, including on window closure, explicit disposal or premature host-dispatcher shutdown. It remains completed for late observers and does not fault or cancel when cleanup fails. Temporary Unloaded does not signal it.

Use this signal to stop forwarding new operations. Concurrent submissions still transfer frame ownership and may return Closed; other operations may throw ObjectDisposedException. The endpoint must drain its own accepted work before releasing its dependencies. Signal completion does not establish resource drainage, resource release or standalone STA exit, and independent leases may outlive the viewer. The owner still awaits DisposeAsync to observe its shared shutdown result; failure does not prove drainage. Continuations are not invoked inline by the signal and have no UI-thread delivery guarantee. Awaiting an already completed task may continue synchronously; do not synchronously wait on the UI thread.

Borrowing viewer capabilities

IViewerCapabilities aggregates the following interfaces and global Layers. IViewer adds IAsyncDisposable. Borrow the aggregate when an adapter needs the complete view; otherwise accept the narrow interfaces it needs. Both hosts implement these on the same instance, without a wrapper or independent lifetime. Only the owning host disposes the viewer. Borrowed capabilities share its STA, state and shutdown gate and have no independent disposal contract.

Submission transfers ownership even when the sink rejects or cancels the frame; alternate implementations and test doubles must release it on every terminal path. Frame readers own their acquired leases. A commit event and a subsequent acquisition are not atomic; use FrameSubmissionOptions.OnCommitted for a specific submission's borrowed lease.

Global layer composition belongs only to IViewerCapabilities.Layers: it can enumerate, create, remove and clear layers across both drawing and measurements. Layers.Items snapshots membership, but its elements remain live mutable handles. IViewerDrawing.Markers and IViewerMeasurements.Measurements expose their respective entire layers; clearing one does not clear the other. A renderer needing a particular layer can accept DrawingLayer; a component updating only an existing drawing can accept DrawingHandle. Layer access includes all content and click handles in that layer, not only the caller's creations.

Measurement events include immutable snapshots and a live editable/removable measurement handle. Measurement tool registration and EndInteraction manage the viewer-wide state; a tool session should use its context's Finish to end only itself. Query configuration affects the shared scheduler for measurements and pixel HUD, including other callers. Menu and HUD handles instead operate on their individual registration or text.

These interfaces describe normal typed dependencies, not security isolation. The same Viewer implements all capabilities and is the sender of viewer events; casts can recover the complete facade. They do not make drawing independent of WPF. Closed is a window notification; the owner still awaits IViewer.DisposeAsync() for complete shutdown.

Event subscriptions

Library-defined events use EventHandler or EventHandler<T> with the existing payload objects or values; T need not derive from EventArgs. Sender is the public object that owns the event: Viewer, ImageViewerControl, DrawingLayer or IMeasurement. Callbacks run on that object's UI/STA thread. IViewerWindow.Closed remains exclusive to the standalone window. WhenStopping is a task and has no UI-thread delivery guarantee.

Adding a subscriber throws ObjectDisposedException once the viewer stops accepting work or the owning layer/measurement is removed. Removing subscribers is safe and idempotent after termination. Duplicate subscriptions invoke multiple times; each removal removes the last matching occurrence. Each notification captures its subscribers: adding during delivery affects later notifications, while removing does not retract already captured or queued callbacks. Final cleanup clears subscriptions. Subscribe before showing the window when closure must be observed; Closed is not replayed. Use WhenStopping for late observation of terminal admission closure.

Subscriber synchronous exceptions are logged individually and do not stop later subscribers or fail the originating operation. Async-void handlers are not awaited; subscribers must manage their asynchronous work and errors. Cleanup callbacks such as IMeasurement.OnDispose retain their separate failure-reporting contract. Event values describe the notification; live handles may already have changed or been disposed. Measurement notifications retain their FIFO and reentrant ordering; frame and drawing-click events do not use that queue.

Related capabilities

  • Measurements: interaction, immutable results and notification order.
  • Custom tools: registration and one-use creation sessions.
  • Menus: registration, target capture and asynchronous execution.
  • Drawing and HUD: layers and individual handles.
